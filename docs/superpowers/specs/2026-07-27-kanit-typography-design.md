# Kanit Typography Design

## เป้าหมาย

ปรับระบบตัวอักษรของเว็บบ้านเงินดีให้ใช้ฟอนต์ Kanit ทั้งโปรเจกต์ เพื่อให้ข้อความภาษาไทยและตัวเลขมีบุคลิกเดียวกัน อ่านง่าย และสม่ำเสมอในทุกหน้า โดยการเปลี่ยนครั้งนี้ต้องไม่กระทบโครงสร้างหน้า ขนาดตัวอักษร น้ำหนักที่ใช้งาน ระยะห่าง หรือพฤติกรรมของส่วนติดต่อผู้ใช้เดิม

## ขอบเขต

- ใช้ Kanit กับข้อความทุกประเภทในเว็บ ได้แก่ เนื้อหา หัวข้อ เมนู ปุ่ม ฟอร์ม ป้ายกำกับ ตาราง ตัวเลข และจำนวนเงิน
- โหลด Kanit จาก Google Fonts ด้วยน้ำหนัก 300, 400, 500, 600 และ 700
- ใช้ `sans-serif` เป็นฟอนต์สำรองเมื่อ Kanit โหลดไม่ได้
- ลบการอ้างอิง IBM Plex Sans Thai และ Manrope ออกจากสไตล์หลักทั้งหมด
- ไม่เปลี่ยนขนาดตัวอักษร `font-weight`, `line-height`, letter spacing, สี, spacing หรือ layout ที่มีอยู่
- ไม่เพิ่มฟอนต์หรือระบบ typography อื่นในงานรอบนี้

## แนวทางการออกแบบ

ประกาศ Google Fonts import สำหรับ Kanit ที่ต้นไฟล์ `apps/web/src/styles.css` และกำหนด Kanit เป็นฟอนต์พื้นฐานบน `body` จากนั้นเปลี่ยนกฎที่ระบุ Manrope หรือ IBM Plex Sans Thai โดยตรงให้ใช้ Kanit เพื่อไม่ให้ข้อความบางส่วนหลุดกลับไปใช้ฟอนต์เดิม

รูปแบบ fallback มาตรฐานคือ:

```css
font-family: "Kanit", sans-serif;
```

การใช้ชุดน้ำหนัก 300–700 รองรับสไตล์เดิมของระบบตั้งแต่ข้อความน้ำหนักเบาไปจนถึงหัวข้อและตัวเลขสำคัญ โดยไม่ต้องแก้ความหนาที่แต่ละคอมโพเนนต์กำหนดไว้แล้ว

## ผลกระทบต่อโครงสร้างและข้อมูล

การเปลี่ยนแปลงจำกัดอยู่ที่ presentation layer:

- ไม่มีการเปลี่ยน React component หรือเส้นทางหน้า
- ไม่มีการเปลี่ยน API, Worker, Supabase schema หรือข้อมูลผู้ใช้
- ไม่มีการเปลี่ยน authentication หรือ onboarding flow
- ไม่มีการเพิ่ม runtime state หรือ business logic

หาก Google Fonts ใช้งานไม่ได้ เบราว์เซอร์จะแสดงฟอนต์ `sans-serif` ของระบบทันที หน้าเว็บยังใช้งานได้ตามปกติ

## การตรวจสอบ

1. ตรวจแบบอัตโนมัติว่า `styles.css` อ้างอิง Kanit และไม่มีคำว่า `Manrope` หรือ `IBM Plex Sans Thai` เหลืออยู่
2. รันชุดทดสอบของโปรเจกต์เพื่อป้องกัน regression
3. รัน typecheck และ production build
4. ตรวจหน้าเว็บบนขนาด desktop และ mobile โดยเน้น:
   - หัวข้อและข้อความภาษาไทย
   - ปุ่ม ช่องกรอกข้อมูล และเมนู
   - ตัวเลข ยอดเงิน และตาราง
   - การตัดบรรทัด ข้อความล้น และการเคลื่อนของ layout

## เกณฑ์สำเร็จ

- ทุกข้อความที่แสดงในเว็บใช้ Kanit เมื่อ Google Fonts โหลดสำเร็จ
- ไม่มีการอ้างอิงฟอนต์เดิมในสไตล์หลัก
- หน้าเดิมยังอ่านง่าย ไม่มีข้อความล้นหรือองค์ประกอบซ้อนกันบน desktop และ mobile
- test, typecheck และ production build ผ่าน

## นอกขอบเขต

- การปรับขนาดตัวอักษรหรือสร้าง typography scale ใหม่
- การเปลี่ยนสี spacing หรือหน้าตาของคอมโพเนนต์
- การ self-host ไฟล์ฟอนต์
- การแก้ส่วน backend หรือฐานข้อมูล
